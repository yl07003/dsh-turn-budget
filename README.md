# dsh-turn-budget — 消费熔断（滑动窗口）

> 目录名/包名 `dsh-turn-budget` 是历史遗留（最早是"回合金额上限"）；现在的功能是**消费熔断**：6 分钟窗口内，**真实余额跌了 ¥10** 或 **token 估算达 ¥7**，就强制暂停所有对话。

## 一道闸，两个触发源，各自独立阈值

| 触发源 | 口径 | 默认阈值 | 特点 |
|---|---|---|---|
| **token 估算（快速）** | 折叠所有会话日志的 `assistant/message.usage`，按模型价位带和时段折算成元 | **¥7** | **零延迟**（每走一步就查）。主力闸——"立刻刹住"靠它 |
| **账户余额（真实）** | 官方账户服务优先（API key 兜底），每 **2 分钟**采一次 | **¥10** | **权威但慢**：实测入账延迟 **30 秒 ~ 3.5 分钟**（官方对其用量数据声明"最多 5 分钟"）。负责"确认真被扣了" |

任一源在 6 分钟窗口内达到**自己的**阈值 → **暂停所有对话**。

**为什么两个阈值不一样**：因为两条源的**时效差了一个量级**。用同一个数字，要么被慢的那条拖到太晚才动手，要么被快的那条频繁误停。所以快的那条收紧（7）、慢的那条放松（10），各司其职。

## 暂停是怎么实现的（很重要）

不是在"某一步"把回合拒掉，而是在 **`llm/stream`（每一次流式模型调用的统一入口）** 上挂起：

- 熔断期间**一个模型请求都不会发出去**，所以不花钱；
- **不丢消息**：请求是"停住等"，不是"被拒绝"，窗口一旦滑过就**自动继续**；
- 覆盖面完整：模型调用、重试、压缩摘要、会话标题、子 agent——全都经过这个入口，没有盲区；
- **安全阀**：单个请求最多挂起"窗口 + 5 分钟"，超时强制放行一个请求并打日志，避免任何情况下把整个 DSH 锁死。

窗口是**滑动**的：条目随时间滑出，6 分钟前的花费不再计入，闸自己就开了。想立刻继续（比如刚充值），点界面上的**「解除暂停」**——它把窗口基准重置到此刻，"重新计时"。

## 界面

输入框下方：**DSH 自带的信息一行，本插件一行**。本插件挂在 Slot `conversation.composer.dock` 上；自带信息（轮数/步数、token、上下文百分比）由 DSH 自己渲染在同一个 dock 行里，**不是这个 slot 的条目**。

```
⏱ 62 轮 302 步 · 257 tok/s    💾 136M tok · 缓存命中 99%               ◐ 17%   ← 自带信息（DSH 提供，绝不改动）
      [谷] [余额 126.00]   最近6min 估算 0.09 / 7 · 真实 0.16 / 10   [7] 估算阈值  [10] 余额阈值  重置默认  解除暂停
```

（上面是**宽度够时**的样子。把输入框拖窄时，本插件这一行会折成两行——读数一行、按钮一行；无论几行都**整行居中、宽度跟随输入框**。）

- **位置与对齐**：本插件**独占自带信息之后的一行**，宽度跟随输入框（拖宽/拖窄都跟着变），**内容以对话框中线为轴居中**；

- **`谷` / `峰`**：当前计费时段徽章，在最前面（只写一个字；**悬停**会显示全称「谷时 / 峰时」与判定口径）。**谷 = 浅绿底**，**峰 = 橘红底**（半透明底色 + 主题色文字，亮/暗主题都可读）。判定口径与官方一致：北京时间周一至周五 09:00–12:00、14:00–18:00 为**峰时**，其余（含周末）为**谷时**（单价减半）。法定节假日未做日历判断，会按工作日算；
- `余额`：官方账户余额（CNY）。读不到时显示"余额 不可用"并给出原因；**余额每 2 分钟才真正采样一次，界面每 1.5 秒重绘一次**（所以数字约 2 分钟才可能变）；
- **重启 DSH 后的头 1–2 分钟，余额数字可能是紫色**：新进程里 DSH 的账户服务要过一会儿才注册，这期间插件走 API key 回退（紫色）；服务就绪后**下一轮采样（≤2 分钟）会自动变回深绿**。**持续紫色**才说明官方账户源有问题——此时状态里的 `accountError` 会写明原因（如 `未登录平台账号` / `平台查询失败`）；
- **余额数字的颜色 = 当前余额来源**：**深绿 `#006400`** = 用的是 DSH 里已登录的平台账号（官方账户服务）；**紫 `#C701FF`** = 平台账号不可用、回退到 API key。**只有余额数字本身变色**——"余额"两个字、读数里的数字、两个阈值输入框都不受影响；
- **余额药丸的底色 = 余额够不够**（2026-09-28 新增）：**≥ ¥50** 浅绿（与"谷"徽章**同底色**，表示充裕）／**¥10 ~ 50** 浅黄 `#FFF9DB`（偏紧）／**< ¥10** 橘红（与"峰"徽章**同色**，告急，等于提前给你一个视觉警报）。读不到余额时**不加底色**；
- `最近6min 估算 0.09 / 7`：窗口内 token 折算花费 / 估算阈值；
- `真实 0.16 / 10`：窗口内余额跌幅 / 余额阈值（`+` 表示期间有充值/退款；窗口未满 6 分钟时把鼠标停在这一行会提示）；
- 两个填空 + 按钮：改金额 → 回车或点对应按钮即生效，持久化。**两个阈值都只接受整数**（小数会被拒绝并提示）；
- **`重置默认`**：把两个阈值一起还原成默认（**7 / 10**），并落盘。它**只动阈值**——不清窗口数据、也不解除熔断（窗口数据被清掉会悄悄削弱这道闸；要立刻放行请用 `解除暂停`）；
- **`解除暂停`**：把窗口基准重置到此刻（充完值想马上继续时用）；
- 熔断时会多出一行红字，写明**是哪个源触发的**（余额还是估算）、以及当前挂起了几个模型请求。

## 参数

| 参数 | 默认 | 怎么改 |
|---|---|---|
| 窗口长度 | **6 分钟** | 代码常量 `WINDOW_MINUTES`（`dsh-turn-budget/index.js` 顶部），改完重启 DSH |
| 估算阈值 | **7**（整数） | 界面填空（或配置文件），小数会被拒绝；`重置默认` 还原成 7 |
| 余额阈值 | **10**（整数） | 界面填空（或配置文件），小数会被拒绝；`重置默认` 还原成 10 |
| 余额采样间隔 | **2 分钟** | 代码常量 `SAMPLE_MS`；另有 `EVALUATE_MS = 30 秒` 只做本地闸门重判（**不联网**）。改完重启 DSH |

> 两个默认值由 `index.js` 顶部的 `ESTIMATE_LIMIT_DEFAULT` / `BALANCE_LIMIT_DEFAULT` 决定。**改常量要重启 DSH 才生效**，而且它只影响"兜底值 / 「重置默认」还原到多少"——只要你在界面上设过值，配置文件里的值就会压过默认值。

配置文件 `%DSH_HOME%\turn-budget.json`：

```json
{
  "estimateLimit": 7,
  "balanceLimit": 10
}
```

（更早版本留下的单阈值 `dropLimit`、以及 `limit` / `windowLimit`，都会被**忽略**；第一次改动时文件被重写成上面这个形状。删掉这个文件并重启 = 回到默认 7 / 10。）

## 能力边界（请务必知道）

1. **余额源有入账延迟**。实测：一笔已知金额的消费发生后，余额要等 **30 秒 ~ 3.5 分钟**才反映出来（官方对其用量数据声明"最多 5 分钟"）。所以余额阈值（10）实际是"服务端可见的最近 6 分钟掉了 10"——真实烧钱到触发可能还要再晚几分钟。**这段空档正是估算源（7，零延迟）存在的理由**。
2. **余额 2 分钟才采一次**，两次采样之间的突发它看不到——这正是估算源存在的意义（也让它从补充变成主力）。
3. **读不到余额时会降级**。非官方 baseURL、缺 `DEEPSEEK_API_KEY`、HTTP 错误、超时——这些情况下真实源失效，只剩估算（7），界面上会明确警告。**它不会因为读不到余额就乱熔断**（宁可漏报也不误停）。
4. **短历史不误报**：启动后不足 6 分钟时，余额跌幅是"从最早样本到现在"的区间，只会少报不会虚报。
5. **挂起 ≠ 中止**：熔断时正在跑的回合会**卡住**（这是"暂停"的字面语义），窗口过了自己继续。如果你更希望它"当场结束回合并告诉你"，那是另一种实现，说一声就改。
6. **旁路调用也算**：余额源天然包含压缩摘要、会话标题这类不进会话日志的花费（这正是它比估算强的地方）。
7. **时段只影响估算**：峰/谷只用于给 token 估算选单价。**2026 年法定节假日已内置**（33 个放假日，工作日节假日按谷时计费；周末与补班日按官方口径本来就是谷时），假期表带覆盖截止与临期提醒（超出表范围的日期回落到星期规则，最多高估 2 倍、偏保守）。权威始终是余额。

8. **`花费` 和 `余额` 行不是同一个口径，别逐秒对比** ✗：`花费 ¥0.45` 是**最近 6 分钟的估算**（每步 token × 价目表，实时出数 ✓）；`余额 -0.13` 是**最近 6 分钟的真实跌幅**（平台按约 60 秒分批落账，最多晚 1–3 分钟 ✓）。所以忙的时候估算"跑在前面"、真实值"补在后面" ✓ —— **同一瞬间差几倍是正常现象** ✗，不代表估算坏了 ✓。想验证准确性，**必须拉长到 15 分钟以上**再比 ✓。
   **实测校准（2026-10-17，16 分钟连续对账）**：估算 ≈ 真实的 **90%**（估算 ¥0.603 / 真实 ¥0.673 ✓）。残余的约 10% 来自**压缩摘要、标题生成**这类不进会话日志的旁路调用 ✓（结构上看不到 ✗，由真实余额兜底 ✓）。此前曾发现过一个真 bug（输入 token 被整笔漏算，估算只有真实的 62%）✓，已修 ✓（`index.js` 改为优先用运行时的 `uncachedInputTokens` ✓）。

### 上限到底是多少（2026-09-28 补充）

**它能保证什么**
- **单步花费有硬上限**：每次模型请求的 `maxTokens` 被 DSH 冻结为 **256K**、上下文上限 **1M**，按价目表折算，**单步最多个位数人民币**；
- **触发阈值后，新增请求全部暂停**（不是丢弃，是停在闸门里），窗口滑回阈值以下**立刻**放行；
- **速率上限 ≈ 10 × 阈值 / 小时**（一次熔断周期 ≈ 6 分钟，每小时约 10 个周期）：估算阈值 **7** → 约 **¥70/小时、约 ¥1,700/天**；只靠余额阈值 10 → 约 ¥100/小时。

**它保证不了什么**
1. **已经在飞的单个请求不会被打断** —— 闸门只在请求发出**之前**检查，所以单次请求可以一次性冲过阈值（好在它受上面那条单步上限约束）；
2. **阈值就是唯一的旋钮，调大等于放弃保护**（可填上限 100000）；
3. **估算看不到不进会话日志的花费**（压缩摘要、会话标题生成等），只有余额源能兜住，而余额源有最多约 3 分钟延迟 —— 两者叠加，**极端情况下仍可能比预期多花一点**；
4. **只保护本机这个 DSH 进程** —— 别的客户端、别的机器用同一个 API key 产生的花费，它拦不住，只能在下次采样时从余额上"事后看见"；
5. **想要精确的额度控制，得靠平台侧的用量限额** —— 这个插件是"**防失控**"，不是"精确预算"。

## 余额从哪来（官方账户服务优先，API key 三级回退兜底）

**首选：DSH 自带的账户服务**。新版 DSH 内置 `deepseekAccount`（用 **DeepSeek 平台账号**登录，浏览器授权），插件直接问它要钱包余额——**不需要 API key、不看 baseURL、不碰凭证文件**，且能用上赠送额度（`bonusWallets`）与充值余额（`value`）之和。命中时状态里的 `keySource` 显示 **`deepseek-account`**。

**兜底：官方 API key 三级回退**：**`credentials` 服务 → 环境变量 `DEEPSEEK_API_KEY` → 凭证文件 `%DSH_HOME%\.credentials.yaml` 的 `refs.DEEPSEEK_API_KEY`**，用来打 `api.deepseek.com/user/balance`。

两者关系是"**官方优先、读不到自动回退**"：账户服务不可用（**没登录**、查询失败、没有 CNY 钱包）时自动走 API key；两条都不通则只剩估算（7）并给黄字警告。所以**不登录也不会变差**，登录后少一层依赖。

为什么要回退：`credentials` 服务在插件激活的那一刻**还没就绪**（实测约 30 秒后才可见，状态里的 `keySource` 会从 `credentials-file` 自动翻成 `credentials-service`）。没有第二、三级回退的话，**每次重启后的头几分钟余额源是瞎的**。密钥只用作 `api.deepseek.com` 的 Authorization 头，不写日志、不下发浏览器。

## 安装

插件以 **`link:`** 方式装进 DSH 的 `web` profile（`dsh web` / `npx @deepseek-ai/dsh web` 用的那个），所以**文件就留在这里**，DSH 每次启动都会加载：

```bat
install.bat
```

等价于：

```bat
npx @deepseek-ai/dsh plugin --profile web add "link:D:/BaiduSyncdisk/1_UM/zzz/DSH-P/dsh-turn-budget"
```

装完**完整重启 DSH**，再**硬刷新浏览器**（Ctrl+Shift+R）。

## 换到另一台电脑 / 移动过目录

`install.bat` 用 `%~dp0` 取自身位置，所以**盘符、同步根、用户名不同都不用改任何东西**，在新机器上直接双击即可。前置件：Node.js，以及 `npm i -g pnpm`（`dsh plugin` 是 pnpm 的转发器）。

**两样东西不会跟着云同步**（它们在 `%USERPROFILE%\.dsh\`，不在本目录）：

1. **API 密钥** —— 新机器的 `.credentials.yaml` 里要有 `refs.DEEPSEEK_API_KEY`（DSH 首次启动会要）。没有它熔断仍工作，但只剩 token 估算那条源，仪表会显示"余额 不可用"。
2. **阈值** —— 新机器从**默认值 7 / 10** 开始；把你在这台机器上设的值填一次，或者把 `turn-budget.json` 拷过去。

另外：**保护是每台机器各自生效的**——一台在跑的东西，另一台的熔断器管不到它自己进程之外的请求（但余额共享，所以另一台会看到余额在掉并触发自己的闸）。别在两台机器上同时改插件文件，云同步会生成冲突副本。

## 更新

改完 `dsh-turn-budget/` 里的文件（`link:` 指向本目录，不用重新 `add`），重启 DSH、硬刷新浏览器即可。

## 卸载

```bat
uninstall.bat
```

跑完**重启 DSH**。`%DSH_HOME%\turn-budget.json` 不会被删除。

## 目录

| 文件 | 作用 |
|---|---|
